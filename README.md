# Redemption Item Creator (PHP)

Online gear/item builder for **Redemption**, the tabletop RPG. It's a PHP port of the
ASP.NET Core API from `F:\Projects\RoutingTest2`, with the same React front end.
Along with SystemGeneratorLive, it's meant to become the core of the new SilentSpirits site.

- **API:** plain PHP 8.0+ and PDO/MySQL. No Composer and no framework, so it runs as-is on Dreamhost shared hosting.
- **Client:** React 19 + Vite, in `client/`.

For the project's purpose, current state, and next steps, see `docs/project_guide.md`. The history is in `docs/change_log.md`.

## Layout

```
public/            Web root: the only folder the web server should expose
  .htaccess        Sends itemcreator/* to api/index.php; everything else falls back to the React app
  api/index.php    Front controller for every API request
  (index.html, assets/ are generated by the client build)
src/               PHP source (namespace SilentSpirits\ItemCreator)
  App.php          Loads config, routes /itemcreator/{action}/..., turns errors into JSON problems
  Controller/      ItemCreatorController: one method per C# action; AuthController: accounts
  Auth/            Session (the sign-in cookie), UserRepository (accounts, one-time tokens), Mailer
  Domain/Item.php  Item model: forgiving input parsing, canonical JSON output
  Repository/      LookupRepository (reference tables), ItemRepository (item CRUD, transactional)
  Export/          ItemCsvExporter, ItemPdfExporter (Dompdf)
lib/               dompdf/ and phpmailer/ (vendored, no Composer), pdf-fonts/ (Andada Pro, Asimovian; SIL OFL)
config/            config.php (gitignored, copy it from config.example.php)
db/migrations/     Numbered SQL schema changes; run each once, in order, on every existing DB
db/seed/           The equipment catalog (catalog.json) and its importer (import_catalog.php)
client/            React source; `npm run build` writes into public/
dev/router.php     Router for PHP's built-in server (stands in for .htaccess locally)
dev/start.mjs      Starts the PHP API and the Vite dev server together (`npm run dev`)
tests/smoke.php    End-to-end test against a running server
api.http           Sample requests for Visual Studio's HTTP editor
```

## Local development

PHP 8.0 ships with IIS Express: `C:\Program Files\IIS Express\PHP\v8.0\php.exe`.

1. `copy config\config.example.php config\config.php`, then fill in the DB credentials
   (local dev: set `allow_writes` and `debug` to `true`, `app_url` to `http://localhost:58967/`, and
   mail `transport` to `'log'`: emails are then written to the system temp dir's `itemcreator-mail/`
   instead of sent, so you can open the confirm/reset links from there).
2. Install the client's packages once: `cd client`, then `npm install`.
3. Start everything:
   - **Visual Studio:** open `RedemptionItemCreatorPHP.sln` and Run. The client project is the
     startup project, and its `npm run dev` starts both servers.
   - **Command line:** `npm run dev` in `client/`.

   Either way, `dev/start.mjs` starts the PHP API on port 5135 (`php -S localhost:5135 -t public dev/router.php`)
   and the Vite dev server, which proxies `/itemcreator` to it. Open http://localhost:58967.
   Stopping Vite stops the API too. If something already listens on 5135, it's reused as the API.
   PHP comes from IIS Express (`C:\Program Files\IIS Express\PHP\v8.0\php.exe`) or `PATH`;
   set `PHP_BINARY` to use another one, and `PHP_API_URL` for another API address.
   `npm run dev:ui` starts only Vite.
4. Run the API tests (needs `allow_writes => true` and mail transport `'log'`; the test makes its own
   `smoke-*@example.invalid` accounts in the DB and removes them):
   ```
   php tests/smoke.php
   ```

To try the production build without Vite, run `npm run build` in `client/` and browse to http://localhost:5135.

## API

Routes match the C# API (case-insensitive), so the React client didn't need changes.

| Method | Route | Returns |
|---|---|---|
| GET | `itemcreator/getitemsizes` | `{ "1": "TINY", ... }` keyed by ItemSizeID |
| GET | `itemcreator/getitemsizesds` | `itemsize` rows |
| GET | `itemcreator/getskillsds` | `skills` rows, by name |
| GET | `itemcreator/getitemattributesds` | `attribute` rows, by name |
| GET | `itemcreator/getattributescaleds` | `attributescale` rows |
| GET | `itemcreator/getallitems` | summaries of the public items, plus the signed-in user's own private ones; each has `source` (the book, null for core) |
| GET | `itemcreator/getitem/{id}` | full item; 404 if missing or someone else's private item |
| POST | `itemcreator/createitem` | 201 + item with new `itemID`, owned by the caller; 401 signed out, 403 email not confirmed |
| PUT | `itemcreator/updateitem/{id}` | 200 + item; replaces all child rows; 404 if missing or not yours; 403 if public |
| DELETE | `itemcreator/deleteitem/{id}` | 204; 404 if missing or not yours; 403 if public |
| GET/POST | `itemcreator/exportitemtocvs/download` | CSV attachment |
| POST | `itemcreator/exportitemtopdf/download` | PDF attachment: the stat block the client builds (`client/src/domain/statBlock.js`) |

Accounts, under `itemcreator/auth/` (JSON bodies; most answer `{ "user": ... }`, the signed-in user or null):

| Method | Route | Does |
|---|---|---|
| GET | `auth/me` | who's signed in |
| POST | `auth/register` | `{ email, password, displayName }`: 202, emails a confirmation link (same answer if the email is taken) |
| POST | `auth/verifyemail` | `{ token }` from the link: confirms the email and signs in |
| POST | `auth/resendverification` | signed in, unconfirmed: emails a new link |
| POST | `auth/login` | `{ email, password }`: 401 if wrong; 429 after 5 failures for an email (20 per IP) in 15 minutes |
| POST | `auth/logout` | ends the session |
| POST | `auth/forgotpassword` | `{ email }`: 202, emails a reset link (1 hour) if there's an account |
| POST | `auth/resetpassword` | `{ token, password }`: sets it and signs in |
| POST | `auth/updateprofile` | `{ displayName }` |
| POST | `auth/changepassword` | `{ currentPassword, newPassword }` |

Passwords need 10+ characters. The session is a PHP session cookie (`SSGS_SESSION`: HttpOnly,
SameSite=Lax, Secure over HTTPS). **Every request that isn't a GET must send `X-SSGS-Request: 1`**
(any value), or it's refused with 403: another site can't add that header, so it can't use a
visitor's cookie to change things here.

Write and export endpoints take the item JSON as the request body. The C# style
(`?Item=<json>` / `?item=<json>` query parameter) still works. Errors come back as
RFC 7807 `application/problem+json`, like ASP.NET's `Problem()`.

The lookup endpoints return byte-for-byte the same JSON as the C# API; this was verified by diffing both servers.

## Changes from the C# version

Bugs fixed:
- **Linux table-name case.** The C# used `Item`/`ITEM`/`item` interchangeably, which works on Windows MySQL but fails on Linux (Dreamhost). Everything is lowercase now.
- **Transactions.** Create/update/delete run in a transaction. A failed write used to leave half-written items behind.
- **Empty attribute list.** Saving an item with no attributes generated invalid SQL.
- **Status codes.** `InsertItem` returned `"fail"` but the controller checked for `null`, and `UpdateItem` returned `"fail"` but the controller checked for `"failed"`, so errors were reported as success.
- **Unknown size.** An unknown `itemSize` was stored as `0`, which hid the item from every JOIN. It's now a 400, and sizes are looked up in the `itemsize` table instead of being hard-coded.
- **CSV quoting.** CSV fields are quoted when needed. A tag like "Harder, Better, Faster, Stronger" used to split across columns.
- **Update/delete of a missing ID.** These return 404 instead of succeeding (an update used to create orphan child rows).

Now saved (the columns already existed but the C# never wrote them):
- `CostRating` → `item.CostRating`
- `AttributeSystem` → `itemattribute.System`

## Deploying to Dreamhost

1. Create the Dreamhost DB from the committed schema and seed files (not written yet; see
   next step 2 in `docs/project_guide.md`). They include every migration so far. After that,
   run any newer `db/migrations/*.sql` on it, in order (on an existing DB, that includes
   `007_users_and_ownership.sql`: the accounts tables, and `008_decisive_action.sql`: new attributes,
   `item.Source` and `item.GroupSize`). Then load the catalog:
   `php db/seed/import_catalog.php` (needs `config/config.php`; see `docs/project_guide.md`).
2. Run `npm run build` in `client/`.
3. Upload the contents of `public/` to the web folder (e.g. `~/silentspiritsgames.com/itemcreator/`).
4. Upload `src/`, `lib/`, `config/`, and the gitignored `Fonts/` (for the PDF's running head) somewhere outside the web root (e.g. `~/itemcreator/`), then uncomment and set
   `SetEnv ITEMCREATOR_ROOT /home/<user>/itemcreator` in the deployed `.htaccess`.
5. Create `config/config.php` on the server from `config.example.php`: the production DB credentials,
   `debug => false`, `allow_writes => true` (saving needs a confirmed account anyway; false makes the
   site read-only), `app_url` (the Gear Creator's public URL: emailed links point there), and the
   `mail` block with transport `'smtp'` and the no-reply mailbox's password. That file is the only
   place the password goes; it's gitignored.
6. Choose PHP 8.1+ for the domain in the Dreamhost panel. The code runs on 8.0, but 8.0 is end-of-life.

Subfolder deployment works: the client uses relative URLs, and the app's own `.htaccess` overrides Joomla's rewrite rules in that folder.
